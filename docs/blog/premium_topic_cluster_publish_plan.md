# Premium Theme Topic Cluster Publish Plan

Last updated: 2026-04-01
Owner: SEO + Content + Frontend
Purpose: Define the first publish-ready topic clusters for blog-led discovery and conversion.

## 1) Objectives

1. Increase non-brand organic discovery for fabric-intent queries.
2. Build stronger internal linking between blog, PLP, and PDP templates.
3. Improve assisted conversion via educational content tied to WhatsApp and product routes.

## 2) Cluster Model

1. Pillar pages: broad, high-intent educational guides.
2. Supporting articles: narrower intent queries under each pillar.
3. Transaction bridge: each article links to relevant shop category/product journey.
4. Recirculation: every support article links to at least one sibling article and one pillar.

## 5) On-Page Standards per Article

1. Include one primary keyword and two semantic secondary variants in title/H2/meta.
2. Add FAQ block where relevant for long-tail capture.
3. Include at least:
   - 1 link to pillar,
   - 1 link to sibling support article,
   - 1 link to shop/category route,
   - 1 soft-conversion CTA (WhatsApp or Contact).
4. Add article schema and breadcrumb schema.
5. Use realistic store-facing examples, avoid generic/demo copy.

## 6) Internal Linking Requirements

1. Blog listing should surface category filters relevant to active clusters.
2. Blog detail pages must include "Continue Exploring" links to:
   - all articles,
   - shop route,
   - category query route.
3. Pillar pages should maintain a section linking every cluster support article.
4. Support articles should link back to pillar in first half of content.

## 7) Success Metrics (First 60 Days)

1. Organic sessions landing on `/blogs` and blog detail routes.
2. Click-through from blog detail to `/shop` and `/shop?category=...`.
3. WhatsApp CTA clicks from blog routes.
4. Assisted conversions where first touch includes a blog route.
5. Avg. engagement time on pillar pages.

## 8) Ownership and Workflow

1. Content: draft and publish article copy.
2. SEO: keyword map, metadata approval, internal-link QA.
3. Frontend: ensure schema and template metadata coverage.
4. QA: verify route health, schema payload presence, and link integrity.
